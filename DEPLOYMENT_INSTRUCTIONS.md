# Инструкция по деплою (развертыванию)

> [!WARNING]
> **ВНИМАНИЕ:** Из-за того, что ранее в консоли разработчики могли переключаться на другие проекты (например, `joiner-dev`), команда `firebase deploy` могла случайно отправлять код **Скин Лаб** на сервер чужого проекта.

## Способ 1: Использовать встроенный защищенный скрипт (Рекомендуемый)

Я добавил специальную команду в конфигурацию (`package.json`), которая принудительно указывает правильный ID проекта — **`skinlab-cms`**. Это исключает любую путаницу с чужими хостингами.

Чтобы правильно собрать и выложить сайт на сервер, выполните в терминале в корневой папке проекта одну команду:

```bash
npm run deploy
```

Она автоматически:
1. Запустит сборку проекта (`vite build`)
2. Запустит загрузку на правильный сервер (`npx firebase deploy --project skinlab-cms`)

---

## Способ 2: Ручной деплой

Если вам необходимо выполнить команду вручную, **всегда** добавляйте флаг `--project`.

```bash
# Правильно:
npm run build
firebase deploy --project skinlab-cms

# НЕПРАВИЛЬНО (может улететь на другой проект):
firebase deploy
```

> **Что делать с прошлым проектом (`joiner-dev`)?**
> Ошибочный деплой на `joiner-dev-a5cff` был исключительно обновлением публичной папки (Hosting) и никак не затронул базу данных вашего или чужого проекта. 
> Чтобы вернуть `joiner-dev` к его нормальному виду, достаточно будет просто запустить `firebase deploy` или `npm run deploy` из оригинальной папки того старого проекта.
